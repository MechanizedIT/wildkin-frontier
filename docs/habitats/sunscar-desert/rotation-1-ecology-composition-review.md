# Sunscar rotation 1 low-ecology composition plan — independent review

**Decision: GO for the bounded removal delta, pending a focused source-contract review before merge.** In the actual arrival and destination portraits, repeated green trail-stone plates compete with the mineral pockets, and the tall Fen stone reads as the wrong wetland/monolith language for Sunscar. Removing the named 12 low, noninteractive instances should improve negative space and leave the existing crystal/ore/fiber and Emberhorn identities more legible. The envelope previews are staging diagnostics only; their brown boxes do not prove the weathered-rib asset or its final composition.

This is a cleanup, not an ecology solution. Deletion alone cannot claim clustered ecology or target likeness. The required post-pass capture must show that retained minerals/forage still form readable edge pockets and that the rooms have not simply become empty. Do not compensate with generic plates or unrelated greenery.

The intended source seam is appropriately narrow only if the implementation applies an exact stable-ID set to **default-world Sunscar low scenery**. It must receive the normalized world descriptor at the existing scenery-generation boundary, return every nonmatching/alternate-world/other-habitat/other-kind spec unchanged, and leave regional-place recipes, canopies, forage, wildlife, homes, global caps, and generated IDs untouched. The 12 IDs must be asserted present in the default candidate set before filtering and absent after filtering; an alternate-world fixture must show none are suppressed. Review that focused source change separately rather than inferring it from this plan.

The suppression must occur at the final desired-record boundary **after** the ordinary sampler has completed its infill/exclusion/cap allocation, in both synchronous sampling and incremental runtime paths (or through one existing visual-suppression owner that covers both). Filtering earlier can alter those allocations and silently repopulate the cleared pocket with other records. Do not add a second owner/framework. The Fen-stone removal intentionally also vacates its current solid collision; name and prove that changed collider/residency count rather than calling every deletion visual-only.
