# Refine the craft inside each production stage

September 14, 2026. Chris observed that the habitat, Wildkin and other workflows need refined guidance for each part of the process, following the tree modeling-director experiment. This is owner workflow direction. The particular stage boundaries below are provisional; they do not authorize a new production batch or claim that all these skills have been implemented.

Subsequent explicit owner requirements: planners must use relevant tool/modeling skills and plans need independent technical review before implementation; each habitat needs its own planning session and high-quality target images. The continuous goal now authorizes repeated habitat/Wildkin visits, while these requirements govern how each visit proceeds. The target author, technical/visual reviewers and builder remain distinct acceptance responsibilities.

## Shared standard

Each repeatable stage needs explicit inputs, owned decisions, a concrete deliverable, visible/functional acceptance evidence, and a bounded repair handoff. The orchestrator composes stages and manages scope/resources; it should not ask a general builder to rediscover every craft decision. Reuse shared stage guidance across habitat, species and assets where the actual work matches. Split a separate skill when it has a distinct reusable responsibility, rather than multiplying overlapping prose.

Refinement must come from observed failures and successful trials. Record the input, planned method, executed method, actual result and independent judgment. A longer prompt, more agents or correct numbers alone does not establish a better result. Preserve human observations separately from agent scores and final admission.

## Implemented first refinement

The [asset modeling director](../.agents/skills/asset-modeling-director/SKILL.md) is project-local and routed from habitat and the forge. It produces target observations/inferences, construction operations, proposed section data, and a target-to-proof table for a separate builder and reviewer. The [Rootbound tree study](../art/source/rootbound-buttress-study/README.md) is its first behavioral trial, using selected guidance from two pinned community packs.

This trial exposed several different failures: an incorrect measured image ratio; instructions for bends that were not enforced in the mesh; correct path numbers with contradictory junction boundaries; and generic surface construction that lost the target's buttress/canopy character. The refined contract addresses these individually. Its general success across other assets remains unproven.
